本页介绍如何从零搭建一个 Copper 模组项目。最好的起点是项目仓库中的 [mod-templete](https://github.com/MDTCopper/loader)（Copper 官方模组模板）。

## 项目结构

一个最小的 Copper 模组项目长这样：

<FileTree>
- my-mod/
	- build.gradle
	- settings.gradle
	- copper.mod.json — 模组元数据（必填）
	- res/
		- assets/  — 原版资源：游戏按原版规则加载
			- bundles/
			- sprites/
			- copper/  — Copper 资源
				- mixins/
					- mindustry.json — Mixin 配置（可选，见 Mixin 专题）
	- src/
		- 你的包名/
			- MyMod.java — 主类，继承 CopperMod
			- patch/
				- impl/
					- MyPatch.java — Mixin 类（可选）
</FileTree>

与 Mindustry 官方模板的差异：

- 元数据文件是 **`copper.mod.json`**（不是 `mod.hjson`），且格式完全不同（见[模组元数据](/developers/mod-meta/)）；
- 主类需要继承 **`CopperMod`**（见[主类与生命周期](/developers/main-class/)）；
- 资源布局上，`assets/` 会被挂载为原版 `LoadedMod` 的资源根，因此原版模组资源（`bundles/`、`sprites/`、`content/` 等）放在 `assets/` 下，而 Copper 自己的资源（Mixin 配置等）放在 `assets/copper/` 下，两者互不干扰（详见[数据、设置与本地化 · 资源文件](/developers/data/#资源文件)）。

## build.gradle

参考模板项目的构建配置：

```groovy
apply plugin: 'java-library'

sourceSets {
    main {
        java.srcDirs = ["src"]
        resources.srcDirs = ["res"]
    }
}

repositories {
    mavenLocal()
    mavenCentral()
    maven { url 'https://www.jitpack.io' }
}

ext {
    copperVersion = '0.1.0'
    // 从 https://github.com/MDTCopper/loader/blob/<copperVersion>/gradle.properties 获取
    mixinVersion = '0.1.3'
    gameVersion = 'v159.7'
}

dependencies {
    compileOnly "com.github.MDTCopper.loader:core:$copperVersion"   // 加载器核心 API
    compileOnly "com.github.MDTCopper.loader:mod:$copperVersion"     // CopperMod 等模组侧 API
    compileOnly "com.github.Anuken.Mindustry:core:$gameVersion"
    annotationProcessor "com.github.MDTCopper:Mixin:$mixinVersion:processor"
}

jar {
    dependsOn configurations.runtimeClasspath
    from ({
        configurations.runtimeClasspath.collect {
            it.isDirectory() ? it : zipTree(it)
        }
    }) {
        include '*'
    }
    from (projectDir) {
        include 'copper.mod.json', 'copper.mod.hjson'
    }
    duplicatesStrategy = DuplicatesStrategy.WARN
}
```

要点：

- 通过 **jitpack** 依赖 `loader:core`（加载器核心，含 `copper.loader.*`）与 `loader:mod`（模组侧 API，含 `copper.core.mod.CopperMod`）；
- `annotationProcessor` 需要 **Mixin 注解处理器**（`com.github.MDTCopper:Mixin:<mixinVersion>:processor`），用于编译期检查 Mixin 注解的正确性；
- `compileOnly` 意味着这些依赖不会被打进 Jar——Copper 模组在运行时由加载器提供这些类；
- Jar 打包时把 `copper.mod.json` 放到 Jar 根目录。

<Aside type="note" title="版本同步">
	`copperVersion` 与 `mixinVersion` 需要匹配。mixin 版本号写在对应加载器版本仓库的 `gradle.properties` 里（`mixinVersion=...`）。
</Aside>

## 最小的主类

一个最小的主类只需要继承 `CopperMod`，甚至可以不覆写任何方法：

```java
package example.examplemod;

import copper.core.mod.CopperMod;

public class ExampleMod extends CopperMod {
    // 构造器在主类实例化时调用
    public ExampleMod() {
    }
}
```

`registerPackets()` 等扩展方法都是可选的，需要时才覆写（见[主类与生命周期](/developers/main-class/)）。

## 构建与安装

<Steps>
1. **构建 Jar。** 在项目根目录执行：

	```bash
	gradle jar
	```

	产物是 `build/libs/my-mod-<version>.jar`。

2. **放入模组文件夹。** 把 Jar 复制到 `<数据目录>/copper/mods/`（见[管理模组](/players/manage-mods/)）。

3. **启动验证。** 启动游戏，日志中应出现：

	```
	Found 2 mods.
	```
</Steps>
