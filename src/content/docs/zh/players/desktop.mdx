本页介绍在**桌面平台**（Windows / Linux / macOS）上使用 Copper。移动设备见[使用移动版](/zh/players/mobile/)。

推荐通过 [Copper Launcher](https://github.com/MDTCopper/launcher) 使用：游戏版本、Java 运行环境、加载器与模组都由它管理。想直接运行加载器 Jar，见[加载器命令行](/zh/developers/cli/)。

## 环境要求

| 项目 | 要求 |
| ---- | ---- |
| 操作系统 | Windows / Linux / macOS |
| Java | **不需要自己准备**：启动器会按游戏版本挑一个兼容的 Java，本机缺了就自动下载 |
| 游戏 | 一个官方 Mindustry 版本；启动器的版本列表里可以直接下载 |
| 加载器 | 用 Copper 加载器启动**要求**官方发行版 **146.0 及以上**或 BE 构建号 **24369 及以上**；更老的版本只能按原版启动 |

## 安装与添加版本

<Steps>
1. **获取启动器。** 从 [MDTCopper/launcher](https://github.com/MDTCopper/launcher) 下载对应平台的发布包（或自行构建），安装后打开。
2. **添加一个游戏版本。** 版本列表取自官方仓库，含正式版、Bleeding-Edge（BE）与历史版本；网络异常时仍可浏览内置快照。
3. **选择怎么启动它。** 要用模组就选 **Copper 加载器**（加载器 Jar 由启动器下载），只玩原版就保持原版。
4. **（可选）开启版本隔离**，让这个版本使用独立的存档与模组配置。
</Steps>

## 启动游戏

点启动即可。启动前可以调整**内存**（按可用内存与模组体积自动分配，或手动指定），也可以附加启动参数、覆盖游戏内设置与多人游戏用户名。启动后可以把启动器收进**系统托盘**，游戏退出后自动弹回。

<Aside type="tip" title="生成启动脚本">
	启动器能把当前版本的启动命令导出成 `.bat` / `.sh`，之后脱离启动器也能启动。脚本里各参数的含义见[加载器命令行](/zh/developers/cli/)。
</Aside>

## 模组放在哪里

用 **Copper 加载器**启动的版本会扫描**两个**模组文件夹：

| 文件夹 | 用途 |
| ------ | ---- |
| `<数据目录>/copper/mods/` | **Copper 原生模组**（元数据文件为 `copper.mod.json` / `copper.mod.hjson`） |
| `<数据目录>/mods/` | **原版 Mindustry 模组**（元数据文件为 `mod.json` / `mod.hjson` / `plugin.json` / `plugin.hjson`） |

`<数据目录>` 默认是 Mindustry 的默认数据位置；开启**版本隔离**后改为该版本自己的数据目录。

| 平台 | 默认 `<数据目录>` |
| ---- | ---- |
| Windows | `%APPDATA%\Mindustry` |
| Linux | `~/.local/share/Mindustry` |
| macOS | 应用支持目录下的 `.mindustry` |

在启动器里也可以浏览、下载、启用或禁用模组，拖入文件即可导入。两种方式等价：**放入 Jar 即安装，删除 Jar 即卸载**。

<Aside type="note" title="核心模组">
	首次启动时，加载器会在 `<数据目录>/copper/mods/` 释放**核心模组** `copper-core.jar`，由它把 Copper 模组接入 Mindustry 的模组系统。**不要删除、改名或禁用**它，否则加载器无法正常工作（启动会报 `core mod is not found`）；升级加载器后首次启动会自动覆盖为匹配的新版本。
</Aside>

## 模组设置

模组自己提供的选项统一收在游戏设置菜单顶部的 **「模组设置」** 页面里，按模组分组显示，并带一个按模组名过滤的搜索框。

修改会**立即写入**模组自己的设置文件（`<数据目录>/copper/datas/<作者-模组名>/`），与游戏的全局设置互不干扰。

## 数据与版本隔离

- **不开隔离**：所有版本共用 Mindustry 的默认数据位置，存档与配置跟着官方游戏走；
- **开启隔离**：每个版本各用一套数据目录，存档、模组与模组配置互不干扰；
- 启动器支持导入 / 导出资源（存档、地图、模组、蓝图，导入功能仍在完善中），可以查看并导出游戏崩溃日志，也会记录每个版本的游玩时长与最近启动时间。

## 更新

| 更新什么 | 怎么做 |
| -------- | ------ |
| 启动器 | 安装新版本覆盖即可 |
| 加载器 | 在版本设置里换成新的加载器 Jar；升级后首次启动会重新释放核心模组 |
| 游戏 | 直接换版本，或添加一个新版本 |
| 模组 | 用新版本文件覆盖旧文件，建议先删除旧的再放入 |

<Aside type="note" title="换游戏版本之后">
	模组通常声明了对游戏版本的要求。换了游戏 Jar（例如从 BE 换回正式版）之后，不满足要求的模组会拒绝加载，这是正常行为——升级游戏时请同时确认所用模组的兼容范围。版本号的构成见[版本、依赖与冲突](/zh/developers/versions/#游戏版本号是如何生成的)。
</Aside>

## 常见问题

### 游戏内不能管理模组

**原因**：这是 Copper 的**预期行为**——由 Copper 启动的 Mindustry 不允许在游戏内导入、移除或启停模组，所有管理操作都在文件层面完成（见[模组放在哪里](#模组放在哪里)）。

### 找不到模组的设置

**原因**：模组设置**不会**各自成为设置菜单的顶层条目，而是统一收在「设置 → 模组设置」里。

**解决**：进入「模组设置」，在页面顶部的搜索框输入模组名定位；对应模组没有出现在列表里，说明它没有提供设置分类。

### 模组没有生效

1. 确认这个版本是用 **Copper 加载器**启动的——原版启动不会加载 Copper 模组；
2. 看启动日志里的 `Found N mods.`：数量比放进去的文件少，通常是文件没有放在上面那两个文件夹里；
3. 依赖缺失、依赖版本不满足或显式冲突都会让模组加载失败，解决办法见[启动报错 · 依赖与冲突错误](/zh/developers/startup-errors/#依赖与冲突错误)。

### 启动失败 / 崩溃

启动器可以查看并导出游戏崩溃日志。自己用命令行启动时，报错对照见[启动报错](/zh/developers/startup-errors/)。
