本页介绍在 **Android 设备**上使用 Copper。桌面设备见[使用桌面版](/zh/players/desktop/)。

移动版同样通过 [Copper Launcher](https://github.com/MDTCopper/launcher) 使用：运行环境、游戏版本与模组都由它管理，设备上不需要自己装 Java——但运行环境**不随安装包自带**，第一次启动要联网下载一份（见下文）。

## 环境要求

| 项目 | 要求 |
| ---- | ---- |
| Android | **11（API 30）或更高版本** |
| CPU 架构 | `arm64-v8a` / `armeabi-v7a` / `x86_64` |
| 游戏版本 | 官方发行版 **146.0 及以上**，或 BE 构建号 **24369 及以上**（两套编号各自独立，互不可比） |
| 存储 | 建议预留 **1 GB 以上**（运行环境、游戏本体与运行期文件都要占地方） |
| 网络 | **第一次启动必须联网**：运行环境不在安装包里，需要下载 |

## 第一次启动

<Steps>
1. **安装并打开启动器。**
2. **等待准备完成。** 启动器会按设备架构**下载**一份 Java 运行环境与运行期组件，解压到应用私有目录。这一步只需要联网做一次，装完才进入主界面。
3. **添加一个游戏版本。** 选择官方发行的桌面版版本（正式版或 BE），并决定是否用 Copper 加载器启动。
4. **点击启动。** 首次启动某个版本时会按需取该版本需要的原生库，之后启动就快了。
</Steps>

<Aside type="note" title="运行环境是下载来的，不随安装包自带">
	安装包里**不含** Java。第一次打开启动器需要一次联网下载，体积不小，建议在 **Wi-Fi** 下进行；下载与解压都会占用应用私有空间。装好之后不必重复下载，除非更换设备或更换 CPU 架构。
</Aside>

## 游戏版本与数据

- 可以同时装多个游戏版本，一次玩一个；
- 开启**版本隔离**后，每个版本各用一套存档、模组与模组配置，互不干扰；
- 游戏数据都在应用的私有目录里，**不需要 root 权限**。

## 模组

模组由启动器管理：浏览并下载，然后启用或禁用。与桌面版一样，管理最终落在文件层面——用 **Copper 加载器**启动的版本会扫描两个文件夹：

| 文件夹 | 用途 |
| ------ | ---- |
| `<数据目录>/copper/mods/` | Copper 原生模组 |
| `<数据目录>/mods/` | 原版 Mindustry 模组 |

**放入 Jar 即安装，删除 Jar 即卸载**。这两个文件夹都在应用的私有目录里，不需要 root 权限，平时交给启动器操作即可。模组自己提供的选项统一收在游戏设置菜单顶部的 **「模组设置」** 页面里。

<Aside type="tip" title="换了模组要做什么">
	重新启动游戏即可，移动版不需要先构建缓存。
</Aside>

## 两种运行方式

同一个游戏版本在移动版上可以有两种运行方式，具体用哪一种由启动器按版本决定，玩家不需要选择。

两者的取舍——游戏版本兼容性、维护成本、启动速度、性能与功耗——见[android-bridge 平台 · 与 ART 路线怎么选](/zh/developers/android-bridge/#与-art-路线怎么选)。

## 更新

- **启动器**：安装新版 APK 覆盖即可；升级后如果运行环境有变化，启动器会重新准备；
- **游戏**：在启动器里换版本，或添加一个新版本，换完直接启动，不需要额外构建；
- **加载器**：跟着版本设置走，同样是换一个 Jar。

## 常见问题

### 第一次启动停在准备页

**原因**：第一次启动要联网下载 Java 运行环境与运行期组件，网络不通或中途断开就会失败。

**解决**：确认网络可用后在准备页重试；页面上会显示失败原因。

### 点击启动后没有反应

**原因**：启动参数有问题、文件缺失这类错误会同步报回启动器；而启动之后发生的失败在游戏进程里，启动器收不到回调。

**解决**：界面弹出堆栈时展开并**复制**它；启动器也可以查看并导出游戏日志与崩溃日志。

### 没有声音或少了功能

**原因**：这个版本需要的**原生库**没有取到，游戏照常能起，但依赖原生实现的那部分功能会缺失——最常见的就是没有声音（也可能表现为其他功能失灵）。

**解决**：保持网络可用后重新启动，让启动器补下该版本的原生库；补齐后仍然缺失，请反馈。

### 存档与模组不见了

**原因**：多半是这个版本开了**版本隔离**——隔离后每个版本各用一套数据目录，切到别的版本自然看不到原来的存档与模组。

**解决**：切回原来那个版本，或把资源导出后再导入到当前版本。
